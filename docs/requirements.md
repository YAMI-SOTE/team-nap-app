## 1. 背景と目的

日中の仕事中は「眠い」「休みたい」と思っても、**周囲が働いている中で自分だけ
休むのは言い出しにくい**。結果として休息が後ろ倒しになり、夜の睡眠と翌日の
集中力が削られる。

Team Nap は、この「休みにくさ」を個人の意志の問題にせず、

1. **いつ休むべきかを自動で判断して提案する**（睡眠リズム × 予定の空き × 直近の休息）
2. **チーム全体で休息を可視化・共有する**（誰が仮眠中か、今週どれだけ休めたか）
3. **休息の結果を記録し、AI がふりかえりコメントを返す**

の 3 点で「休むことを当たり前にする」ことを目的とする。

### プロダクトゴール

| # | ゴール | 現在の測り方（アプリ内） |
| --- | --- | --- |
| G1 | ユーザーが適切なタイミングで短い仮眠を取る | `NapRecord` の件数・時間帯・`wakeStars` |
| G2 | 休息がチームの当たり前になる | 今週の休息スコア達成人数 / 全員が仮眠した日数 |
| G3 | 休息が集中力に効いたと実感できる | `focusDeltaPt`（仮眠前後の集中度差）と週次コンディション |

## 2. スコープ

### 2.1 対象（v1 = 現行実装）

- モバイルアプリ（React Native / Expo）。iOS / Android 実機 ＋ **Web ビルド**
  （審査・デモ用に Vercel 公開、[split-deployment.md](./split-deployment.md)）。
- 1 ユーザー = 1 アカウント = **最大 1 チーム**。
- 日本語 UI のみ。時刻・日付はすべて **JST 固定**。
- 「今週」は**カレンダー週（日曜〜土曜）**。ローリング 7 日でも月曜始まりでもない。

### 2.2 対象外（v1 では作らない）

| 項目 | 理由・現状 |
| --- | --- |
| 1 ユーザーの複数チーム所属 | `TeamMembership.@@unique([userId])` で DB レベルで禁止 |
| 複数端末の同時ログイン | 意図的に禁止（FR-A5） |
| メール送信基盤 | パスワード再設定トークンはサーバログ出力（＋非本番はレスポンス） |
| 課金・組織管理・SSO | 未着手 |
| 休息提案の履歴・受諾率の永続化 | 判定ロジック（`rest-decision.service`）のみ存在。`RestRecommendation` テーブルは未実装 |
| API の水平スケール | WebSocket 在席ハブがプロセス内状態。単一インスタンス前提 |
| ダークモード / 多言語 | 未対応 |

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| **仮眠（Nap）** | 日中の短い睡眠。タイマーは既定 15 分 |
| **休息スコア** | 0–100。`仮眠回数×15 + 平均wakeStars×8 + 平均focusDelta` を 0–100 にクランプ（`lib/rest-score.ts`）。個人統計・チーム統計・ランキング・ホームのチームスコアで**同一の式**を使う |
| **在席ステータス** | `作業中 / 仮眠中 / オフライン`。DB は `online / resting` の 2 値で、`オフライン` は時間経過から導出 |
| **ナッジ** | メンバー同士の「起きて〜」「休んでね」の一声。通知として届くが履歴は残さない |
| **チーム仮眠提案** | 1 人が「N 分仮眠しませんか」と他メンバー全員に投げる通知 |
| **空き時間** | その日の `CalendarEvent` の隙間。15 分以上のものだけを休息候補にする |

## 4. 想定ユーザー

| ペルソナ | 状況 | 期待 |
| --- | --- | --- |
| P1: 日中デスクワーカー | 午後に集中力が落ちる。休憩の切り出しが下手 | 「今休んでいい」と背中を押してほしい |
| P2: チームリーダー | メンバーの疲労が見えない | チームの休息状況を一目で把握したい |
| P3: 個人利用（チーム未所属） | 1 人で使い始める | チーム機能抜きでも仮眠の記録・統計が使える |

P3 のため、**チーム未所属でもアプリは成立する**こと（FR-H2）が要件になる。

## 5. 機能要件

ID は `FR-<領域><番号>`。優先度は **必須 / 推奨 / 任意**。
「状態」列は 2026-09-20 時点の実装状況。

### 5.1 認証・セッション（A）

| ID | 要件 | 優先 | 状態 |
| --- | --- | --- | --- |
| FR-A1 | メールアドレス + パスワード（8 文字以上）で新規登録・ログインできる | 必須 | ✅ |
| FR-A2 | ログイン失敗時、アカウントの存在有無が推測できない文言を返す（常に 401） | 必須 | ✅ |
| FR-A3 | セッショントークンは不透明なランダム文字列で、DB には SHA-256 ハッシュのみ保存する | 必須 | ✅ |
| FR-A4 | セッションの有効期限は `SESSION_TTL_HOURS`（既定 720h = 30 日） | 必須 | ✅ |
| FR-A5 | **1 アカウント = 1 端末。** 生きているセッションがある状態で別端末がログインを試みたら 409 で断る（**先にログインしている端末が勝つ**） | 必須 | ✅ |
| FR-A6 | FR-A5 で締め出された場合の復帰手段が 3 つある: 元端末でサインアウト / `logout-others` / パスワード再設定（全セッション失効） | 必須 | ✅ |
| FR-A7 | パスワード再設定は単回・期限付き（既定 60 分）トークン。存在秘匿のためリクエストは常に 202 | 必須 | ✅ |
| FR-A8 | ログイン中のパスワード変更は現在のセッションを残し、他を失効させる | 必須 | ✅ |
| FR-A9 | Google アカウントでログイン / 既存アカウントへの連携ができる（Authorization Code + PKCE、client secret はバックエンドのみ保持） | 推奨 | ✅ コード実装済み。Google Cloud Console と env 未設定時はボタンが「現在ご利用いただけません」 |
| FR-A10 | アカウント削除ができ、関連データは cascade で消える | 推奨 | ✅ |

### 5.4 休息判定（R）

判定ロジックは `backend/src/services/rest-decision.service.ts`。
入力は「普段の就寝時刻 / 今日の最後の仮眠終了時刻 / 現在時刻（JST）/ 今日の空き時間」。

| ID | 要件 | 優先 | 状態 |
| --- | --- | --- | --- |
| FR-R1 | 15 分以上の空き時間が無ければ提案しない（`NO_FREE_TIME`） | 必須 | ✅ |
| FR-R2 | 就寝 2 時間前以内は提案しない（`TOO_LATE`） | 必須 | ✅ |
| FR-R3 | 直近 60 分以内に仮眠していたら提案しない（`RECENTLY_RESTED`） | 必須 | ✅ |
| FR-R4 | 必要度スコアを「今日まだ休んでいない or 前回から 120 分以上経過」+1、「現在 13:00–16:00」+1 で算出し、**2 点以上**で提案する（未満は `NO_REST_NEEDED`） | 必須 | ✅ |
| FR-R5 | 候補の空き時間は「13:00–16:00 に始まる」+2、「60 分以内に始まる」+1 で採点し、同点なら早い方を選ぶ | 必須 | ✅ |
| FR-R6 | 推奨する仮眠時間は 15 分固定 | 必須 | ✅ |
| FR-R7 | 提案の履歴と受諾フラグを永続化する | 任意 | ❌ 未実装（`RestRecommendation` テーブル無し） |

| FR-N4 | **起床アラームは端末のローカル通知**で鳴らす（画面を閉じた / 端末がロックされた状態でも鳴る必要があるため） | 必須 | ✅ |

## 7. 前提・制約

- **単一インスタンス前提。** WebSocket ハブがプロセス内状態（`byTeam` / `byUser`）
  のため、API を水平スケールするには socket レジストリの共有（Redis pub/sub 等）が別途要る。
- **Web ビルドでは Expo プッシュが存在しない。** realtime socket が唯一の即時配信経路。
- **シミュレータではプッシュが動かない**（`!Device.isDevice` で return）。フィードは通常どおり動く。
- **Ollama の RAM 要件。** 既定モデル `gemma4:e2b` は ollama サービスに ~8GB RAM / 2CPU を要求する。
  足りないホストでは `OLLAMA_MODEL=gemma3:1b` に落とす（日本語はやや不自然になる）。
- モノレポだが npm workspaces ではない。依存は `backend/` と `mobile/` で別々に入れる。
