# 機能テストガイド

認証・オンボーディング・チーム機能をひと通り手で確認するための手順。
アカウント / スケジュールの一覧は [test-account.md](./test-account.md)、
セットアップ全般は [setup.md](./setup.md) を参照。

---

## 0. 準備

```bash
# 1) DB + Backend
docker compose up -d db
cd backend && cp .env.example .env        # 初回のみ
npm install && npm run db:migrate && npm run db:seed && npm run dev

# 2) 別ターミナルで Mobile
cd mobile && npm install && npx expo start
```

`mobile/.env` の `EXPO_PUBLIC_API_URL` は実行環境に合わせる:

| 実行環境 | 値 |
| --- | --- |
| iOS シミュレータ / Web | `http://localhost:3000/api/v1` |
| Android エミュレータ | `http://10.0.2.2:3000/api/v1` |
| 実機 | `http://<PCのLAN IP>:3000/api/v1` |

疎通確認: `curl http://localhost:3000/api/v1/health` → `{"status":"ok",...}`

## 1. アカウント作成・ログイン

| # | 手順 | 期待結果 |
| --- | --- | --- |
| 1.1 | Splash → ログイン画面 → 「新規登録」 | **サインアップ画面**へ（オンボーディングではない） |
| 1.2 | サインアップ画面を見る | 4項目（名前 / メール / パスワード / 確認）+ ボタンが**スクロールなしで1画面に収まる** |
| 1.3 | `sample@teamnap.app` で新規登録 | 「このメールアドレスは既に…」等のエラー（重複 → 409） |
| 1.4 | パスワードを `short`（8文字未満）で登録 | バリデーションエラー |
| 1.5 | 新しいメール + 8文字以上で登録 | 成功 → **オンボーディング画面**へ遷移（`onboardingCompleted:false`） |
| 1.6 | 一度ログアウトし、誤ったパスワードでログイン | 「メールアドレスまたはパスワードが違います」= 入れない |
| 1.7 | 正しいパスワードでログイン | オンボーディング済みなら `/home`、未済なら `/onboarding` |

### パスワードを忘れた

1. ログイン画面 → 「パスワードをお忘れですか？」→ 再設定画面
2. メール入力 → 「リセットリンクを送る」
   - 開発ビルドはレスポンスに `resetToken` が入るので**自動入力**される
   - サーバコンソールにも `[password-reset] token for <email>: <token>` が出る
3. 新パスワード（8文字以上）を2回入力 → 「パスワードを再設定」
4. **「パスワードを再設定しました」のポップアップ** → 「ログインへ」
5. 旧パスワードでログイン不可 / 新パスワードでログイン可（全セッション失効）

### パスワードがハッシュ化されていること

`NODE_ENV !== production` のとき有効:

```bash
TOKEN=...  # ログインの token
curl -s http://localhost:3000/api/v1/auth/debug -H "authorization: Bearer $TOKEN"
# => { "passwordHash": "scrypt$<salt>$<hash>", "passwordHashAlgorithm": "scrypt", ... }
```

生パスワードは保存されません。

## 2. オンボーディング（サインアップの後）

| # | 手順 | 期待結果 |
| --- | --- | --- |
| 2.1 | 新規登録直後 or 未オンボーディングのアカウントでログイン | オンボーディング画面に入る |
| 2.2 | 未ログインで `/onboarding` に来る（想定外経路） | `/signup` に戻される（保存にセッションが要るため） |
| 2.3 | 「睡眠リズム」スライド | 「あとで設定する」が**無い** → 起床/就寝を確認して「つぎへ」しないと進めない |
| 2.4 | 「カレンダー」スライドで「カレンダーを連携する」 | **「カレンダーを連携しますか？」ポップアップ**（Web でも動く）。「連携する」でも「あとで」でも次へ進める |
| 2.5 | 「通知」スライドで「はじめる」 | `POST /onboarding/complete` → `/home`。失敗時はインラインでエラー表示＆再試行可 |
| 2.6 | 完了後もう一度 `GET /auth/me` | `onboardingCompleted: true` |

**デフォルト / バックフィル**: サインアップ時に `Onboarding` 行がデフォルト値
（`bedtime 23:30` / `wakeTime 07:30`）で作られます。オンボーディング導入前の
ユーザー（`b@teamnap.local` 等）は行が無いため、初回 `GET /onboarding` で
デフォルト行が遅延作成され `completed:false` になり、質問画面へ誘導されます。

| `hanako@teamnap.app` | サンプル 花子 | resting | on |
| `jiro@teamnap.app` | サンプル 次郎 | online | **off** |
| `saburo@teamnap.app` | サンプル 三郎 | resting | on |

| # | 手順 | 期待結果 |
| --- | --- | --- |
| 4.1 | 太郎でログイン → チームタブ | チーム名「サンプルチーム」、**メンバー4人**（別チームの人は出ない）。「仮眠中 2 / 作業中 2」 |

### curl での確認（任意）

```bash
B=http://localhost:3000/api/v1
TARO=$(curl -s -XPOST $B/auth/login -H 'content-type: application/json' \
  -d '{"email":"sample@teamnap.app","password":"samplepass123"}' | jq -r .token)

curl -s $B/settings/team -H "authorization: Bearer $TARO"          # メンバー4人
curl -s -XPOST $B/teams/members/20000000-0000-0000-0000-000000000002/rest \
  -H "authorization: Bearer $TARO"                                  # 花子へ「休んでね」
curl -s -XPOST $B/teams/members/20000000-0000-0000-0000-000000000003/wake \
  -H "authorization: Bearer $TARO"                                  # 次郎へ「起きて〜」→ 409
curl -s -XPOST $B/teams/nap-suggestion -H "authorization: Bearer $TARO" \
  -H 'content-type: application/json' -d '{"minutes":20}'           # {"success":true,"notified":3}
```

## 5. 実装済み / 未実装（重要）

### ✅ 実装済み・テスト可能

- **休息を勧める（ナッジ）**: メンバー詳細の「休んでね」「起きて〜」。相手の
  通知フィードに `rest_request` / `wake_request` が積まれる。起床サポート off の
  相手への wake は 409。（バックエンド `POST /teams/members/:id/{rest,wake}`）
- **チーム仮眠の提案**: 「◯分仮眠を提案」。自分以外の全メンバーへ
  `team_nap_suggestion` を配信。（`POST /teams/nap-suggestion`）
- メンバー一覧・在席ステータスの**表示**、チーム作成 / 参加 / 改名 / 退出。

### ⚠️ 未実装 — テスト対象外

- **在席ステータスのライブ更新はありません。** メンバーの「作業中 / 仮眠中」は
  画面を開いたときに 1 回だけ取得する**スナップショット**で、ポーリングも
  WebSocket もプッシュもありません。アプリ内に**自分のステータスを変更する
  UI もありません**。表示される状態はシード値のまま（太郎/次郎=作業中、
  花子/三郎=仮眠中）で、セッション中に自動では変わりません。
  - バックエンドには `PUT/GET /api/v1/teams/me/status` があり
    `TeamMembership.activity` を更新・取得できますが、フロントからは未接続です。
- **通知フィードはインメモリ**（`Map`、サーバ再起動で消える）。ナッジや仮眠提案の
  結果を確認するときは、間にサーバを再起動しないこと。
- 今週の Team Nap サマリー / 仮眠上手ランキング / 統計の数値は**固定のダミー**
  （仮眠履歴からの算出は未実装）。ランキングのメンバー（メンバーA〜K）は
  実チームと無関係。
- メンバー詳細の「仮眠の状況」カード（`nap`）は常に空（ライブ仮眠セッション未実装）。
- Google ログインは未対応。

## 6. スケジュール / カレンダー

`GET /api/v1/schedule/day?date=YYYY-MM-DD`。予定は
[test-account.md](./test-account.md) の「サンプルスケジュール」表と一致します
（2026-09-01〜14）。`09-03` / `09-10` / 週末は予定なし（空き時間テスト向け）。
スケジュールは**全体共有のインメモリ**（ユーザーごとではない）。

## 7. バックエンド接続エラー画面

1. アプリを起動してログイン済みの状態にする
2. `backend` を止める（`Ctrl+C` / `docker compose stop backend`）
3. チームタブ or 統計タブを開き直す
4. **「接続できません / ネットワークの状態を確認して…」＋「再読み込み」** が全面表示
5. `backend` を戻して「再読み込み」→ 通常表示に復帰
